# GitHub Flow

1. Crie uma branch a partir da branch principal.
2. Faça as mudanças nessa branch e salve o trabalho em commits com mensagens claras.
3. Abra um Pull Request e explique o que você mudou.
4. Peça a revisão de um colega. Se ele pedir um ajuste, faça a mudança na mesma branch. O novo commit aparece no Pull Request que já está aberto.
5. Depois da aprovação, faça o merge para integrar as mudanças à branch principal.
6. Apague a branch de trabalho depois do merge.

## Por que usamos uma branch?

A branch permite preparar as mudanças enquanto a equipe continua usando a main. Com o Pull Request, o colega consegue ver o que mudou e pedir ajustes antes de integrar o trabalho.

## O que significam as cores do diff?

O vermelho mostra as linhas removidas e o verde mostra as linhas adicionadas. Se a gente trocar uma palavra em uma frase, por exemplo, o diff pode mostrar a linha antiga em vermelho e a nova em verde.
